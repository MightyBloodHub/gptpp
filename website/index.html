The language

What does an agent need to make an edit?

A wrong return value gives an agent an outcome. GPT++ also gives it the expressions that produced that outcome, in a form it can inspect and change.

Values from a real call
Run an example through the interpreter. Its JSON trace pairs expressions with their types, execution counts and observed values, including the local variables in scope.
An address for each expression
Every site in the trace has a byte range tied to the source revision. A model can submit one replacement even when the same expression appears twice.
Feedback before review
The repair tool explores a bounded set of replacements and tests candidates against public examples. A reviewer can inspect the resulting diff before applying it.

Quickstart

Follow one call through the compiler.

Build gpp with the pinned Rust toolchain. Run main(), then trace the call it makes to add. Both commands run locally.

Read the language reference

examples/add.gpp

module demo.main;

fn add(left: I64, right: I64) -> I64 !{} {
    return left + right;
}

pub fn main() -> I64 !{} {
    return add(20, 22);
}

Build and run

git clone https://github.com/MightyBloodHub/gptpp.git
cd gptpp
cargo build --locked --offline
target/debug/gpp check examples/add.gpp
target/debug/gpp run --interpreter examples/add.gpp

Compiler compatibility replay

Three saved edits ran correctly with new scalar operations

A model wrote this expression to find the smallest whole-tick count that covers a delay in milliseconds. Its algorithm needed the remainder test to produce 0 or 1. The earlier compiler rejected the explicit conversion.

milliseconds / 1000
  + (milliseconds % 1000 != 0) as I64

The language now supports as I64 for booleans and integer min, max and clamp. We rebuilt and tested the exact saved model replies on this compiler.

Compiler measurement

Checking many proposed edits in one process

gpp probe checks a batch of independent expression edits against one source revision in a single compiler process. The repair and distinguishing-input tools use it to evaluate candidates. We timed six repair searches and three searches for distinguishing inputs.

Across these workloads the speedup was 21.10× on this host. Individual changes ranged from 1.01× for an empty Go menu to 39.18× for FastLED’s distinguishing inputs. The sum of median CPU times fell from 26.21 to 1.27 seconds. Both debug builds returned identical menus and questions across all three repetitions.

Program measurement

Running the corrected programs

Each reference program made two million calls and produced the same checksum in every language. GPT++ and Rust ran as optimized native executables with checked arithmetic. Python ran under its interpreter.

Elapsed time includes process startup. Peak resident memory and elapsed time are medians of three runs on the same Mac. Build time is one measurement per program and includes bytecode compilation for Python.

GPT++ had the lowest observed runtime and peak memory on each loop. Rust built its native programs faster. Native runs took only 7–8 milliseconds, so startup and scheduling affect the ordering.

Which example would tell the edits apart?

Six FastLED edits passed the original examples. GPT++ ran them on unlabeled inputs and found calls where their answers differed. An independent implementation of the scaling rule supplied the expected value for just two calls.
