# Retrospective replay of frozen GPT++ expressions

Two sets of development trials captured complete model requests and replies before the compiler gained explicit `as I64` conversions and native `min`, `max` and `clamp` calls. Inspecting failed expressions motivated those changes. This is a retrospective language adaptation. The original three-language results continue to describe the original compiler and are preserved in their archives.

Take every GPT++ trial from both blocks (three historical and three locally authored tasks, two models, 12 trials). Score every raw answer, preserving its exact site ID, replacement expression, source bytes, ordering and original task. Rebuild the compiler catalog and verify the original UTF-8 span. Apply through the real checked editor. Run the same public and withheld scorer as before. An edit passes only if it compiles and passes all public and withheld cases. In the primary trial summary, stop at the first reply that passes the public checks, even if that choice subsequently fails withheld. Separately record every archived reply's individual outcome. No new prompt, localization, retry, model inference or oracle label is allowed. Charge the original input and output tokens from all calls even if the first reply now passes.

After each accepted choice on the locally authored tasks, run a further direct-call grid against independent arithmetic oracles. The signed accumulator uses all 169 pairs from {-1000, -101, -100, -99, -2, -1, 0, 1, 2, 99, 100, 101, 1000}. The timeout uses each multiple of 1000 from 0 to 100000 inclusive with offsets −1, 0, 1 and 999 within the domain, plus 9,999,999 and 10,000,000. The membership grid uses all points and both endpoints from {-1000, -101, -5, -1, 0, 1, 4, 73, 1000} with start ≤ end. These additional inputs test the selected patches and never affect a choice. Report tested counts and mismatches. A measured improvement here cannot be substituted for a fresh comparison against Python or Rust.
