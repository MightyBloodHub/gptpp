# Frozen checked-edit pilot

The unit is one newly authored family. Three scalar changes and three state-machine changes each have four labeled commissioning examples, a single typed return-expression hole, a public rule and an independently executable finite acceptance property. Score all six in all five arms in GPT++, typed Python and Rust. Keep the eleven CodingBat tasks and both reservation and scalar repair demos for development and regression only. No rerun of these families after a policy change qualifies as fresh evidence.

## Decisions and budgets

* **Direct** asks Qwen once and publishes only after the public gate passes.
* **Direct retry** starts the same way, with one more call after a public rejection. It reveals the rejected expression and says it failed.
* **Direct witness** has the same budget and includes the local site, actual public input, observed result and violated rule on retry. Comparing these two arms isolates the effect of the diagnostic for direct generation.
* **Search** runs GPT++ piecewise completion with 256 roots, 10,000 finite assignments per verification and a 60-second process timeout. It checks the returned expression or the two distinguishing alternatives. It has no model or label source.
* **Workflow** uses the same search and gate. When both alternatives survive, it can ask once at the distinguishing input. The named public specification can answer within the declared bounds. Otherwise it abstains. A rejected compiler proposal can trigger one model repair. With no proposal, one initial generation and at most one repair are available. An unsupported or incomplete check never licenses publication.

GPT++ uses the shipped checker, revision-bound slot fill, verifier and interpreter. All arms compare finite examples separately from the exact acceptance property. All languages edit the same typed function over the same state and inputs. For Rust and Python the public property is checked by strict native execution against the independent total public answer on the identical finite product. All model arms get the same English rule and examples. Successful native candidates must pass rustc or strict mypy. Search proposals are translated from the **same** GPT++ search. The first public disagreement identifies the native observation for feedback. Compiler receipts retain richer diagnostics than the compact matched model prompts. These are workflow comparisons with shared search and bounded native properties. They do not independently compare three synthesis engines.

## Preparation and scoring

Calibrate each property independently of the example gate using its positive reference and intentionally incorrect old expression. Check translations against the public specification on every declared input. As a separate, charged preparation exercise, ask Qwen once per family for an incorrect implementation that fits the public examples. Record where its attempt fails or passes. Only calibration uses these candidates. Report the observed packet preparation interval, the 24 manual labels, every audited proposal, solver/validation time, external questions and all model usage. Charge the entire shared setup once per standalone six-task arm. Show incremental deployment cost separately. Codex authoring tokens and a human equivalent were unmetered. Report that gap explicitly.

A development smoke check ran the six correct references against the scorer before freeze. No candidate was scored during that check. During collection only a separate scoring process opens the hidden behavioral oracle, after every attempted edit, model receipt and final decision is closed on disk. Score the scalar changes on new out-of-domain inputs. Score the state machines on every event word of lengths 1–5, checking caller state after every prefix. Identical transitions can be batched by their concrete inputs. For a failing history only its first divergent step uses the reference prefix state. Calibrate the sealed scorer on references and starters after close. Output hashes bind the scores to the decision log.

## Primary decision criterion

Compare workflow against one-call direct Qwen in GPT++. The proposed engineering target is **at least 20% fewer metered tokens per independently correct change** with a prespecified noninferiority margin of **2 percentage points** for correctness. Count every assigned task, every failed attempt and full preparation for an isolated deployment. The correctness endpoint is the fraction of assigned tasks published and passing every sealed case. A wrong publication and an abstention both fail this endpoint and are reported separately. First pass means publication before any model repair. Report both its public and sealed result. Zero correct changes leave tokens per correct undefined.

Require the lower end of a conservative 95% paired interval for the correctness difference to be at least −0.02 and the upper 95% paired family-bootstrap bound for the charged cost ratio to be at most 0.80. Bound the win and loss probabilities with simultaneous exact binomial intervals (Bonferroni), then subtract their endpoints. Enumerate all 46,656 resamples of six whole paired families, including their corresponding preparation charges, with replacement. Use the 2.5th and 97.5th percentiles. Treat an undefined resample as occupying its full possible range for the reported bounds. Report undefined ratios. The secondary direct-repair, search and language comparisons are descriptive. Six nonrandom synthetic families, one pinned model and one seed cannot establish a general language advantage or human preparation cost.
