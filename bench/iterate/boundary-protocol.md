# Stop at the end of a function gap

Qwen's earlier native infill run rejected every Rust submission at the structural edit boundary. A model that emits a function closer and starts a test or a second function can spend tokens on text outside the requested edit. Test whether stopping in the model server improves accepted changes and reduces actual generated tokens.

Use Qwen2.5-Coder 7B on eight new scalar tasks. Randomize tasks and conditions with seed 7307. Assign all seven conditions to every task. Native GPT++, Python and Rust each get an ordinary infill condition and a stopped condition. Within a language, only the additional provider stop strings differ. For braced languages, stop before a newline followed by a column-zero closing brace. For Python, stop before a column-zero function, class, import, assertion, print, test entry or decorator. A malformed or prematurely stopped fragment still fails the same structural checks. Record the literal strings on each request. Preserve the original model defaults by including its stop sequences in each stopped request.

An exploratory stopped Python-syntax condition translates to checked GPT++ using the extended scalar adapter. The prompt includes the real GPT++ starter and signed integer rules. Compare native GPT++ stopped against typed Python stopped (primary) and Rust stopped, and compare the exploratory arm with Python stopped. Keep all open/stopped within-language contrasts. All conditions use the previous infill prompt, source prefix and suffix, with the same two-call repair, examples, temperature, seeds and context/token limits. Count all actual input and generated tokens in the assigned workflow. Preflight all three languages' references against their public and hidden oracles, plus incorrect maintenance starters. Keep withheld cases out of requests. Report paired task-level uncertainty and the original acceptance and efficiency bounds. This is an independent development set of eight task families.
