# Ask for the result of a distinguishing input

Freeze the menus from all three development fixtures in the six-trial repair archive. The menus were identical across models, so count each task once. This follow-up was designed after reviewing the first-candidate control, abstentions and the retrospective menu audit. Its output cannot alter the original model trials.

Supply these ordered, unlabeled pools of calls to each target, independently of candidate predictions. Iterate each Cartesian product left to right with the last coordinate varying fastest.

| Target | Probe arguments in order |
|---|---|
| Redis access timestamp | clock ∈ {17, 501, 8388608, 16777210}, duration ∈ {13, 713, 6811}, multiplier ∈ {1, 1000} |
| FastLED byte scaling | level ∈ {11, 37, 103, 169, 207, 241}, fraction ∈ {23, 59, 97, 151, 193, 237, 249, 253}, fixed mode ∈ {false, true} |
| Go period boundary | year ∈ {1964, 1973, 2037, 2176}, elapsed second ∈ {43567, 12700123, 28000567, 31000432} |

Check that no probe repeats a named public or withheld call before execution. Probe inputs carry no oracle outputs. Invoke the product CLI on the full surviving menu and the same input pool each round. If it asks a question, compute exactly one answer and retain the group with that result. Use a distinct implementation of the published semantics for answers. For Redis, step the clock backwards by the integer number of elapsed ticks with the historical wrap rule. For FastLED, use an exact rational weight on the 256-step grid, including the mode offset. For Go, compute the successive transitions and year length using calendar dates. The oracle receives only the chosen function and arguments. Never ask it to label the rest of the pool.

Stop on an empty menu, a singleton, no candidate matching the answer, or agreement on every probe. For agreement, take the first surviving ID and disclose the unresolved tie. Evaluate its public and withheld behavior only after the selection is fixed. No model call, retry, candidate regeneration or change to the input pool is allowed. Archive the questions, candidate partitions, labels, final choice, independent behavioral check and wall time. Report accepted tasks, extra labels and probe evaluations separately. The comparison measures a workflow with an external answer source on three previously inspected fixtures.
