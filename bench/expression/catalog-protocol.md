# Compiler-listed selections

Early v9 responses selected declarations, copied protected suffixes or failed the two-line change format. This development follow-up tests an alternative on all three v9 tasks in all three languages with both installed models. The tasks have already been seen during development. The original comparison stays frozen.

Generate one completion per task, language and model. Give the model the change request, up to three public examples, the original target function, and a source-ordered list of every selectable expression in that function. Identify each expression by an ordinal and line number. Allow repeated expressions to have distinct IDs. Constrain the output to a JSON object with a listed ID and a free-text replacement. Compile the proposed change and run public and withheld cases with the v9 adapters. A public or hidden failure ends the trial. The correct site, reference and hidden results play no role in generation.

The same renderer and schema builder serve the product CLI and each language. Run through the installed model's ordinary prompt template with seed 42, greedy decoding, a 2,048-token context and 240 output tokens. The schema goes to the decoder outside the text prompt. Record its serialized size separately. Charge every reported input and generated token, even when the proposal fails. This comparison changes the representation, decoding constraints and prompt transport together. It measures their joint effect. Compare first-attempt acceptance and tokens per accepted edit against the original two-call and combined workflows, then across the three languages. Randomize task/language assignment order once with seed 30992 per model. Publish the complete 18 trials and replay the archived responses.
