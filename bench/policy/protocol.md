# Ordered-rule maintenance pilot

Frozen before scored model calls. The primary question is whether a checked list of ordered exceptions with a compiler-owned fallback reduces total tokens per accepted edit by at least 20% relative to typed Python with the same fallback. Qwen2.5-Coder 7B is the primary model for continuity. StarCoder2 3B is a prespecified replication. Each model has eight paired task families and seven arms. The experimental unit is the task. Token counts from different tokenizers are reported separately.

The arms are GPT++ rules, GPT++ native, typed Python and Rust. All three native surfaces get both an entire-body edit and an insertion immediately before the protected starter body. The rule arm starts with a fixed `when ` and ends with a fixed `else => @keep`. It may insert several ordered exceptions or cover every input. Native insertions may use any supported statements, including unconditional returns. Each arm gets the same change specification, public examples, target declaration and original body once. Only the syntax instructions vary. The model must infer which cases should change. No hidden data, reference implementation, caller source or oracle-backed patch search contributes to the first prompt.

The first public failure naming a caller triggers exactly one retry with the previous insertion, the public mismatch and bounded caller excerpts. A checker failure, target failure or hidden failure ends the trial. Report both this adaptive workflow and its observed first-call-only result. A budget of 240 generated tokens and 2,048 context tokens applies to every call. Seed 42 and greedy decoding are used first, then seed 43 and temperature 0.25 for the retry. All calls within a model run serially in a fixed shuffled order. Qwen uses its installed suffix template. StarCoder2 uses raw prefix/suffix/middle markers and stops on its file and infill control tokens. [BigCode tokenizer](https://huggingface.co/bigcode/starcoder2-3b/blob/54da76775f65ecde085d6e75aa17a053b043900e/tokenizer_config.json) · [BigCode infill construction](https://huggingface.co/spaces/bigcode/bigcode-playground/blob/main/app.py)

The corpus consists of eight hand-selected, source-derived, bounded decision-policy reproductions with at least two unchanged downstream functions each. Reference programs in all three languages must pass every public and withheld case. Each starter must fail a change and preserve some withheld behavior in two callers. A scored submission must survive scoped patching, language checking, the public examples and the withheld tests. The evaluator executes model outputs in the previous maintenance sandbox.

Count every assigned call, including failures, and divide all input plus output tokens by the number of accepted edits. Report acceptance, time, costs of retries and distance from a ratio of 0.80. Use the existing 10,000-draw paired task bootstrap and the Section 19.7 gates (acceptance lower bound at least −0.02 and cost ratio upper bound at most 0.80). Zero accepted edits leave the cost per success undefined. Break out all native comparators. A result shared by equivalent native insertions cannot establish a language-specific advantage. This targeted, single-seed pilot can guide development. A broader claim requires independent projects, larger tasks and additional samples. Frozen tasks must never be used to tune a rerun that is labeled fresh.
