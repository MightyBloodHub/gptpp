# Matched state-transition changes

Freeze four new single-hole maintenance requests in independent stateful task families after the compiler and completion interface is specified and before exposing tasks to the product engineers or collecting model replies. The known reservation-cancellation example is excluded. Each program has two state fields, a three-variant event, an initial state and one typed expression hole inside one protected transition. The common fixture definition renders equivalent native state/event declarations, transition branches and contract inputs into GPT++, typed Python and Rust. Supply the original expression at the hole and the requested behavior to all arms. An independent history-based implementation supplies expected end states.

For each task give models its full visible native state transition, the named hole and type, every public event sequence and expected full state, and a language-specific syntax card with the same operations. Accepted input is a single native expression in a JSON object with a string field named `expression`. Only state projections, signed integer and Boolean literals, arithmetic, comparisons, Boolean operations, native conditionals and the listed pure scalar helpers may appear. Statical checking and public sequence evaluation gate publication. Use actual GPT++ checked hole filling, strict mypy plus Python execution, and checked Rust compilation plus execution. Prefix the retry with the previous response and at most 600 characters of compiler diagnostic or a public failing sequence. Never show withheld sequences, their scores or repair choices. Zero external clarifications by design. One first attempt, then at most one retry after a public or type rejection. Stop on a public pass even if withheld checks later fail.

Run both pinned local Ollama models, Qwen2.5-Coder 7B then StarCoder2 3B, on all twelve task/language pairs per model. Shuffle each model's pairs with seed 61213. Use identical JSON schema, normal model template, temperature zero, 4096 context, maximum 200 output tokens, and seeds 42 and 43 for first attempt and retry. Archive every attempted edit and charged input/output tokens. Report first and final independent correctness, model calls, retries, clarification count, end-to-end authoring time, model round trips and residual local tool/overhead time. Charge failures. Report both resource totals and tokens per accepted change where estimable.

Independently score every published change on all event words of lengths 1 through 6, excluding the visible public words. Each expected result checks both state fields. Numeric ranges stay safely inside signed-64-bit limits for correct implementations. The independent oracle works from pointer roles, inventory objects, run lengths or event-history segments, instead of reusing the program's proposed expression. Preflight each language's original and reference programs and verify that the starter fails public behavior while the reference passes every public and withheld check.

As a no-model control, enumerate a fixed, language-independent sequence of at most 64 typed expressions from the hole's scope and choose the first public-passing one in each language. Use the same ordering, model-free information and finishing rules across all three backends. Report any disagreement, the earliest selected expression and independent correctness. Separately run GPT++'s built-in `complete` with the same limit; its candidate grammar, ordering and ambiguity checks can differ. Compare model-backed language results only within the three matched native arms. The sample comprises four task families, and repeated models do not add independent tasks.

Measure shared specification authoring as elapsed wall time from starting the neutral task/contract design to freezing this protocol and the independent oracle. State who authored it and exclude setup, implementation, subsequent verification and model time. There is no human labor measurement and no measured language-specific human authoring time; distinguishing shared one-time effort from per-trial costs is essential to interpreting this benchmark. Publish the frozen task inputs, source hashes, raw trial data, complete commands, exclusions and offline replay.
