The language

          
How does an agent finish an open decision?

          
The reservation module uses records for state and enums for booking decisions. A typed hole lets an agent leave one expression open while keeping its callers and behavioral contracts intact.

        

        

          

            
Fill a typed hole

            
Replace the repeated-cancellation outcome with ?repeat: Outcome. The compiler tested 25 expressions, found five that passed the finite contracts, and selected Outcome::Ok. The completed module matched the shipped source byte for byte. Run the completion

          

          

            
Ask when the contract leaves a choice

            
Leaving the available seat count open produced two passing behaviors. The compiler asked about a repeated cancellation with eight seats free. One candidate kept eight seats available. Another capped the answer at two.

          

          

            
Prove cancellation across the integer range

            
The native CLI can send supported predicates to Z3. The reservation proof covers repeated cancellations and unknown IDs at every nonnegative I64 seat count. It also covers cancelling an active booking twice wherever releasing one seat fits in I64. The solver proved eight obligations in the combined module. Compiler compatibility replay

            
Three saved edits ran correctly with new scalar operations

            
A model wrote this expression to find the smallest whole-tick count that covers a delay in milliseconds. Its algorithm needed the remainder test to produce 0 or 1. The earlier compiler rejected the explicit conversion.

            
milliseconds / 1000
  + (milliseconds % 1000 != 0) as I64

            
The language now supports as I64 for booleans and integer min, max and clamp. The compatibility replay tested the exact saved model replies on the release that introduced these operations.

We chose these operations after inspecting the original failures. StarCoder2 remained at 0 of 3 on the new contracts, and neither model solved a historical fix on replay.

Program measurement

            
Running the corrected programs

            
Each reference program made two million calls and produced the same checksum in every language. GPT++ and Rust ran as optimized native executables with checked arithmetic. Python ran under its interpreter.

            
Elapsed time includes process startup. Peak resident memory and elapsed time are medians of three runs on the same Mac. Build time is one measurement per program and includes bytecode compilation for Python.

            
GPT++ had the lowest observed runtime and peak memory on each loop. Rust built its native programs faster. Native runs took only 7–8 milliseconds, so startup and scheduling affect the ordering.
